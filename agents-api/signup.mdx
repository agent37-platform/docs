---
title: "Sign up"
description: "Create a workspace and an API key with one unauthenticated call, so an agent can onboard itself and start paying."
---

`POST /v1/signup` creates a workspace, a login, an empty [wallet](/agents-api/billing), and your first API key in one call. It is the only endpoint on the Sandbox API that takes no `Authorization` header, because it is where the key comes from.

Use it when the caller is a program. If you are a person, [sign up in the dashboard](https://www.agent37.com/dashboard/cloud/api-keys) instead: you get the same workspace and the same key, on a screen.

## Sign up and start running

<CodeGroup>
```bash curl wrap
# 1. Get a workspace and a key. No credentials needed.
SIGNUP=$(curl --fail-with-body -sS -X POST https://api.agent37.com/v1/signup \
  -H "Content-Type: application/json" \
  -d '{"email": "agents@example.com", "name": "Acme Agents"}')
export AGENT37_API_KEY=$(printf '%s' "$SIGNUP" | jq -er '.api_key')

# 2. Fund the wallet: open the link and pay.
printf '%s' "$SIGNUP" | jq -er '.top_up_url'

# Hand this to the human who owns the email to give them the dashboard.
printf '%s' "$SIGNUP" | jq -er '.claim_url'

# 3. Create an instance with the key from step 1.
curl --fail-with-body -sS -X POST https://api.agent37.com/v1/instances \
  -H "Authorization: Bearer $AGENT37_API_KEY"
```

```python Python wrap
import os
import requests

signup = requests.post(
    "https://api.agent37.com/v1/signup",
    json={"email": "agents@example.com", "name": "Acme Agents"},
)
signup.raise_for_status()
account = signup.json()

api_key = account["api_key"]
print("Fund the wallet:", account["top_up_url"])
print("Claim the dashboard:", account["claim_url"])

instance = requests.post(
    "https://api.agent37.com/v1/instances",
    headers={"Authorization": f"Bearer {api_key}"},
)
instance.raise_for_status()
print(instance.json())
```

```javascript Node wrap
const signup = await fetch("https://api.agent37.com/v1/signup", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email: "agents@example.com", name: "Acme Agents" }),
});
if (!signup.ok) throw new Error(await signup.text());
const account = await signup.json();

console.log("Fund the wallet:", account.top_up_url);
console.log("Claim the dashboard:", account.claim_url);

const instance = await fetch("https://api.agent37.com/v1/instances", {
  method: "POST",
  headers: { Authorization: `Bearer ${account.api_key}` },
});
if (!instance.ok) throw new Error(await instance.text());
console.log(await instance.json());
```
</CodeGroup>

Every other endpoint on this reference works with the key from step 1: it is a full workspace key, so it creates instances, manages templates and domains, reads [usage](/agents-api/billing#read-workspace-usage), [funds the wallet](/agents-api/billing#fund-the-wallet-from-the-api), and [adds members](/agents-api/members). Store it the way you would store any secret, and treat it as able to spend money.

## Request

<ParamField body="email" type="string" required>
  Where to reach the workspace's owner, and the address its `claim_url` is scoped to. It is not a login, and it is not verified. Every call creates a new workspace, the same address included, so if a response is lost, call again: the key is shown only once.
</ParamField>
<ParamField body="name" type="string" post={["optional"]}>
  The workspace name, up to 100 characters. Defaults to a name derived from the email address.
</ParamField>
<ParamField body="top_up_usd" type="number" post={["optional"]} default="5">
  What `top_up_url` is worth, \$5 to \$10,000. It only sizes the returned payment link; nothing is charged by this call.
</ParamField>

## Response

<ResponseField name="workspace_id" type="string">
  The workspace the key belongs to. Everything the key creates is owned by it.
</ResponseField>

<ResponseField name="api_key" type="string">
  Your `sk_live_` key, shown once and never again. The account has no other key until you mint one.
</ResponseField>

<ResponseField name="email" type="string">
  The address the account was created on, lowercased.
</ResponseField>

<ResponseField name="balance_usd" type="number">
  Always `0`. Fund the wallet before creating an instance.
</ResponseField>

<ResponseField name="top_up_url" type="string">
  A hosted Stripe Checkout link for `top_up_usd`. `null` if the link could not be created, in which case [`POST /v1/billing/top-up`](/agents-api/billing#fund-the-wallet-from-the-api) mints another one.
</ResponseField>

<ResponseField name="top_up_usd" type="number">
  The amount `top_up_url` charges.
</ResponseField>

<ResponseField name="claim_url">
  An admin invitation link for `email`, so a human can take over the workspace in the dashboard. Give it to the person who owns that address. See [The email, and who owns the account](#the-email-and-who-owns-the-account).
</ResponseField>

## The email, and who owns the account

The address is a contact address and a claim ticket, not a login. Nothing is emailed, and the workspace is owned by an account that has no email address and no password, so nobody can sign in as it. That matters because this endpoint is unauthenticated: if it registered a login on the address you send, anyone could sign up `someone@theircompany.com` and keep a working key in the workspace that person later landed in.

`claim_url` is how a human gets in. It is an ordinary admin invitation scoped to the address you signed up with, so give it to the person who owns that address. They sign in (or sign up) with it and accept, which makes them a full admin: from there they mint and revoke keys, see the ledger, fund the wallet, and manage the team in the dashboard. The link does not expire and is used once.

That is the intended path to a second key. There is no endpoint that mints keys, on purpose: a key that can mint keys is no protection, because a stolen one just mints another.

Signing up does not touch any Agent37 account that address may already have.

An account created by `POST /v1/signup` does not receive the one-time \$5 starter credit. That credit exists so a person can try the product before paying; fund the wallet to start.

## Fund it, then create

A new workspace is on the free tier: balance \$0, and one instance once it is funded. Creating an instance with an empty wallet returns `402 insufficient_balance`, which is the signal to pay. Until the wallet holds money, [cloud template builds](/agents-api/templates#build-an-image-in-the-cloud) and [member invitations](/agents-api/members) return `402 insufficient_balance` too. The first top-up of any amount raises the ceiling to 10 instances. See [Billing](/agents-api/billing) for the tiers, the rates, and how to pay.

```text
POST /v1/signup          -> workspace_id, api_key, top_up_url, claim_url
POST /v1/billing/top-up  -> open the Checkout URL
GET  /v1/billing         -> balance_usd, tier, instance_limit
POST /v1/instances       -> a running sandbox
```

## Errors

| Status | Code | Meaning |
| --- | --- | --- |
| `400` | `invalid_request` | `email` is missing or malformed, or `top_up_usd` is outside \$5 to \$10,000. |
